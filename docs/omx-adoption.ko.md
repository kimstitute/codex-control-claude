# OMX 도입 노트

이 문서는 설치된 oh-my-codex(OMX) 설계 중 현재 컨트롤러 구현에 적합한
부분을 기록합니다. 이는 도입(adoption) 노트이며, 컨트롤러가 이미 팀
런타임이라는 주장이 아닙니다.

## 소스 근거

참조 프로젝트는 [Yeachan-Heo/oh-my-codex](https://github.com/Yeachan-Heo/oh-my-codex)입니다.
이 노트를 위해 검토된 로컬 설치는 OMX 0.20.5입니다. 관련 소스 경로는 그
설치를 기준으로 한 상대 경로입니다:

- `dist/agents/definitions.js` — 역할 레코드: 이름, 설명, reasoning effort,
  자세(posture), 모델 클래스, 라우팅 역할, 도구 클래스, 카테고리.
- `dist/agents/native-config.js` — 결정론적 자세/모델 오버레이와 네이티브
  서브에이전트 리프(leaf) 가드.
- `skills/team/SKILL.md` — 네이티브 서브에이전트와 지속적인 tmux 팀
  런타임의 구분, 그리고 상태 우선(state-first) 디스패치와 터미널 모니터링.
- `skills/worker/SKILL.md` — 클레임 안전(claim-safe) 태스크 생명주기, 워커
  상태, ACK, 메일박스 전달.
- `prompts/architect.md`, `prompts/critic.md`, `prompts/executor.md`,
  `prompts/verifier.md` — 역할별 경계와 승인 기준.

이 파일들은 재사용 가능한 계약(contract)에 대한 증거입니다. 이들은 이
컨트롤러의 의존성이 아니며, 그 런타임 코드는 이 컨트롤러에 복사되지
않습니다.

## 현재 구현 슬라이스

현재 슬라이스는 의도적으로 OMX 오케스트레이션보다 작습니다:

1. **역할 라우팅**은 명시적이며 각 어사인먼트마다 영속화됩니다. 일상적인
   구현과 제한된 수정에는 Sonnet을 사용합니다. 계획, 아키텍처, 비평,
   중대한 검증에는 Fable을 사용합니다. 호출자가 공급한 모델/역할 오버라이드는
   기록되며 기본 정책보다 우선합니다. 조용한 폴백은 허용되지 않습니다.
2. **프롬프트 스냅샷**은 결정론적입니다. 컨트롤러는 정규화된 역할, 태스크,
   해석된 모델, 기능(capability) 안내, 출력 계약을 하나의 정규(canonical)
   JSON 프롬프트로 저장합니다. 기존의 실행 의도(run-intent) 지문은 그
   정확한 프롬프트와 실행 파라미터를 포괄합니다. 두 번째 태스크
   데이터베이스나 사이드카 파일은 없습니다.
3. **구조화된 어사인먼트**는 명시적인 태스크 아이덴티티, 소유자, 예상
   모델, 제한된 공급 텍스트 페이로드를 가집니다. 컨트롤러는 하나의 명확하게
   정의된 어사인먼트를 기존 로컬 Claude 프로세스 경계에 위임합니다.
4. **보고와 승인은 분리되어 있습니다.** Claude는 요약, 산출물, 증거,
   한계, 핸드오프를 담은 구조화된 보고서를 반환합니다. 컨트롤러는 그
   형식을 확인합니다. 레거시 v1 보고서는 `unreviewed` 상태로 남으며, v0.3
   태스크 리비전은 정확한 실행과 다이제스트에 바인딩된 명시적인 Codex
   승인을 추가합니다. 검토자의 추천만으로는 승인이 아닙니다.
5. **태스크 리비전과 승인 원장(ledger)**은 불변의 입력, 정확한 부모
   컨텍스트, 조작 중복 제거, 추가 전용 기준 증거를 보존합니다. 제출은
   리비전과 실행을 동일한 예약 트랜잭션에서 연결합니다.
6. **관찰(observation)은 실행에 대해 읽기 전용입니다.** 컨트롤러는 알 수
   없는 세션을 채택하거나 조종하거나 대체하지 않고도 여러 기존 로컬 실행
   ID와 그 최종 기록을 조회할 수 있습니다.

이 슬라이스는 큐, DAG 스케줄러, 리스(lease) 서비스, 메일박스, 장기 실행
데몬, tmux 런타임, Claude 도구/MCP, 호스트 간 디스패치를 전혀 추가하지
않습니다. 역할 의도와 검증 증거를 명시적으로 만들면서도 기존의 Linux 공급
텍스트 프로필을 그대로 유지하려는 것이 목표입니다.

## 네이티브 서브에이전트 대 OMX 팀

OMX는 네이티브 서브에이전트를 리더가 직접적인 결과를 기다리는 세션 내
제한된 팬아웃(fan-out)으로 설명합니다. 그 tmux 팀 모드는 다른 운영
방식입니다: 지속적인 공유 태스크 상태, 워커 메일박스, 디스패치 파일,
생명주기 명령, 하나의 추론 버스트보다 오래 지속될 수 있는 pane을
추가합니다. 현재 컨트롤러는 제한된 어사인먼트 시맨틱스와 명시적인 로컬
태스크/검토 기록을 채택합니다. 그러나 Claude 서브프로세스를 OMX 워커인 척
하지 않으며, 정확성을 위해 tmux, pane 텍스트, 또는 합성 키 입력을 요구하지
않습니다.

이식 가능한 규칙은 상태 우선(state-first)입니다: 어사인먼트는 실행되기
전에 로컬 컨트롤러에 의해 승인되어야 하며, 그 결과는 동일한 어사인먼트
ID와 다시 연결되어야 합니다. 향후 비동기 코디네이터가 추가되더라도 이
규칙을 유지해야 하며, 프로세스 출력이나 UI를 큐로 사용하는 대신 진정한
영속적 큐를 추가해야 합니다.

## 여전히 유효한 기존 보호 장치

OMX 역할 도입이 컨트롤러의 기존 보호 장치를 약화시키지는 않습니다:

- 세션별 직렬화와 단일 활성 작성자(writer);
- 멱등(idempotent) 요청 아이덴티티와 모호한 재시도 거부;
- 서버/설치 소유권 확인과 호스트 불일치 거부;
- 명시적인 요청 모델 대 실제 모델의 기록;
- PID만이 아니라 Linux 시작 틱, 부팅 아이덴티티, PID 네임스페이스를
  사용한 프로세스 아이덴티티 확인;
- Claude 도구와 MCP가 비활성화된 상태의 공급 텍스트 실행;
- 로컬 워크스페이스, 자격 증명, 트랜스크립트, 컨트롤러 상태 경계.

기존의 SQLite 클레임과 영속적인 실행 기록은 여전히 로컬 승인의 근원
(source of truth)입니다. 프롬프트 역할이나 보고서는 리스(lease)를
부여하거나, 워크스페이스를 잠금 해제하거나, 알 수 없는 세션을 채택하거나,
두 번째 작성자를 승인할 수 없습니다.

## 이후 단계의 불변식

향후 비동기 위임이 추가된다면, 테스트와 검토된 상태 머신 변경을 동반한
별도의 단계로 도입되어야 합니다. 최소한 다음을 증명해야 합니다:

- 클레임이 원자적이고 소유권에 바인딩되어 있음;
- 모든 클레임이 일회용(single-use) 멱등 키와 영속적인 리비전을 가짐;
- 응답 손실이 모호한 Claude 실행의 재시도를 유발하지 않음;
- 취소와 프로세스 종료가 요청 승인과 별개로 보고됨;
- 결과 발행이 원자적이며 정확한 어사인먼트와 프롬프트 스냅샷을 참조함;
- 오래된 워커가 더 새로운 컨트롤러 epoch를 업데이트할 수 없음;
- 예약이 해제되기 전에 터미널 모니터링이 검증된 상태에 도달함.

OMX의 메일박스/ACK와 상태 우선 생명주기는 그 단계를 위한 유용한 설계
참조이지만, 컨트롤러의 SQLite 클레임, 프로세스 펜싱(fencing), 또는
reconciliation 규칙을 대체하지는 않습니다. 마찬가지로, tmux는 이러한
불변식이 그것과 독립적이 된 이후에만 선택적인 디스플레이 또는 실행
어댑터가 될 수 있습니다.

## 비목표와 미해결 우려

이 노트는 Windows 지원, 호스트 간 통신, 원격 MCP, GitHub 전송, 또는
무인(unattended) 운영을 확립하지 않습니다. 또한 Fable 세션 재개/포크나
임의의 기존 세션 채택이 안전하다는 것도 확립하지 않습니다. 이러한 기능은
별도의 호스트 로컬 프로브와 명시적인 계약을 필요로 합니다.

가장 중요한 미해결 우려는 의미적(semantic) 승인입니다: 구조화된 출력은
증거를 기계 판독 가능하게 만들지만, 연구 결과나 코드 결과가 참(true)임을
증명하지는 않습니다. 호출자 또는 별도의 검증자는 결과를 사용하기 전에
관련 테스트, 검토, 또는 산출물 검사를 제공해야 합니다. 실행 상태가 승인을
의미하는 것은 결코 아닙니다.

## 구현된 P2: 영속적인 로컬 디스패치

버전 0.4는 다음 슬라이스를 구현합니다: 제한된 FIFO 대기, Codex 승인으로
게이트되는 정확한 태스크/리비전 의존관계, 불변의 복사된 실행 입력, 유한하고
명시적인 디스패치, 영속화된 이벤트. SQLite 트랜잭션과 기존 워커 클레임은
중복 예약을 방지합니다. tmux, 데몬, 리스 서비스는 추가되지 않습니다.
코디네이터 재시작은 이전 실행을 다시 시작하지 않고 관찰만 합니다.
[큐 조작](queue.ko.md)을 참고하세요. 아래에서 설명하듯 P3 메시지와 P4
검토 워크플로우는 이 디스패치 계층 위에 구축됩니다.

## 구현된 P3: 명시적인 다음 턴 지시사항

버전 0.5는 Codex가 선택한 지시사항 메시지와 고정된 결과 핸드오프를
추가하며, 정확한 기본 리비전 확인과 추가 전용 전달 영수증을 포함합니다.
이는 텍스트를 터미널 pane에 주입하거나 에이전트에 재귀적 위임 권한을
부여하지 않으면서 유용한 영속 메시지 아이디어를 채택합니다. 실행 영수증은
이해(comprehension)나 의미적 승인과는 별개입니다. 제한된 검토/수정
워크플로우는 아래의 P4에서 추가됩니다.

## 구현된 P4: 고정된 검토 워크플로우

버전 0.6은 태스크 리비전, 큐 승인, 메시지를 결합해 고정된 제안/검토/수정
템플릿을 만듭니다. 영속적인 예산, 정확한 기준별 검토 결정, 주의(attention)
요약을 추가합니다. OMX의 tmux 감독, 재귀적 스폰(spawning), 상주 코디네이터는
채택하지 않습니다. [워크플로우 동작](workflows.ko.md)을 참고하세요.

## P5: 명시적인 워크스페이스 권한

버전 0.7은 컨트롤러가 중재하는 파일 읽기, 전체 파일 쓰기, 명명된 격리
검사를 위한 별도의 유한한 워크스페이스 루프를 추가합니다. 이는 기존
Claude 안전 모드와 태스크 이력을 유지하고, 독립적인 검토를 위해 결과를
고정하며, 통합은 Codex에게 맡깁니다. 이는 tmux 제어, 네이티브 도구 접근,
재귀적 에이전트, 자동 병합을 도입하지 않으면서 명시적인 소유권과 검증
경계를 채택합니다. [워크스페이스](workspaces.ko.md)를 참고하세요.


## 버전 0.8: 정규화된 실행 설정

OMX 0.20.5 설치는 이 슬라이스를 위해 다시 검토되었으며, 특히
`dist/team/model-contract.js`(argv 정규화 및 명시적/기본값 우선순위)와
`dist/team/runtime.js`(고정된 워커 실행 계획과 영속적인 시작 상태)가
검토되었습니다. 참조 프로젝트는 MIT 라이선스입니다. 이 컨트롤러는 그
패턴을 독립적으로 구현하며, OMX 런타임 코드, 의존성, tmux 메커니즘은
복사되지 않습니다.

우리는 하나의 검증된 argv 표현, 실행 전 해석된 설정의 영속화, 재개 시
세션에 저장된 값의 재적용을 채택합니다. Claude는 OMX/Codex의
`model_reasoning_effort` 설정 대신 `--effort`를 사용합니다. 형식이 잘못된
입력은 조용히 폐기되는 대신 실패합니다. OMX의 워커 시작 대기 제한은 이
컨트롤러의 모델 실행 기한과는 다릅니다.

Claude는 effort를 세션 전용으로 문서화하며 effort 환경 변수는 오버라이드로
문서화합니다. 따라서 컨트롤러는 모든 실행마다 고정된 effort를 다시
전달하고 그 환경 변수는 제외합니다. 그 다섯 값의 열거형(enum)은 명시적으로
유지되며, `doctor`는 설치된 플래그 지원을 확인할 뿐 모든 모델/값 조합을
확인하지는 않습니다. 공식 [CLI 레퍼런스](https://code.claude.com/docs/en/cli-reference),
[환경 변수 레퍼런스](https://code.claude.com/docs/en/env-vars),
[헤드리스 세션 가이드](https://code.claude.com/docs/en/headless)를 참고하세요.
