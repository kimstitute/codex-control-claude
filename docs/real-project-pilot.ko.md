# 첫 번째 실제 프로젝트 파일럿

첫 번째 파일럿은 이 저장소의 워크스페이스 정책 검증기(validator)를 실제
제한된 유지보수 태스크로 사용했습니다. 의도된 순서는 Sonnet의 편집, 격리된
단위 검사, 독립적인 Fable 검토, 명시적인 Codex 검증이었습니다.

**자동 에디터 시퀀스는 이 파일럿을 통과하지 못했습니다.** 완료된 모델
프로세스와 유용한 코드 제안만으로는 조작을 승인하기에 충분하지 않았습니다.
컨트롤러는 실패한 시도를 그대로 보존했으며, 그 제안된 쓰기나 검사를 실행하지
않았습니다.

## 무슨 일이 있었는가

- 첫 Sonnet 세션은 승인된 두 파일을 읽었습니다. 그다음 호출은 300초 제한을
  초과했고 사용 가능한 결과를 반환하지 못했습니다. 워크스페이스가
  중단되었습니다.
- 종료를 확인하고 첫 번째 시도를 보존한 뒤, Codex는 공급된 소스 텍스트와
  900초 제한으로 별도의 시도를 명시적으로 생성했습니다. 이는 자동 재시도나
  모델 교체가 아니었습니다.
- 그 호출은 약 431초 만에 완료되었지만, 최상위 JSON 키가 반복되어
  있었습니다. 엄격한 보고서 검증이 어떤 파일 조작도 이루어지기 전에 이를
  거부했습니다.
- Codex는 제안된 파일 텍스트를 별도로 검사했습니다. 그 제안은 기존의 NUL
  인자 가드도 잘못 변경했는데, 기존의 회귀 테스트가 그 변경을
  포착했습니다. Codex는 가드를 복원하고 유니코드 테스트를 확장했습니다.
- 수정된 후보(candidate)는 읽기 전용 Fable 검토를 위해 불변의 비공개 Git
  스냅샷에 배치되었습니다. 이는 별도의 Codex 감독 복구 경로이며, 거부된
  에디터 태스크에 대한 고정 내보내기나 승인이 아닙니다.
- Fable은 유효한 보고서 턴 2개를 완료했고, 컨트롤러를 통해 수정된 두 파일을
  모두 읽었으며 **APPROVE**를 권고했습니다. Fable은 공급된 테스트 증거와
  자신이 직접 실행하지 않은 검사를 명확히 구분했습니다. 실제 완료된 모델
  ID는 `claude-sonnet-5`와 `claude-fable-5-1`이었으며, 네이티브 도구
  호출은 0건이었습니다.

이러한 관찰은 하나의 제한된 태스크에 관한 것입니다. 이는 일반적인 지연
시간이나 모델 성공률을 확립하지 않습니다. 실패한 시도, 원본 응답, 아이덴티티는
비공개 컨트롤러 기록에 남아 있으며, 여기서 배포되지 않습니다.

## 결함과 수정

기존 정책은 경로 및 검사 인자에서 Python 서로게이트(surrogate) 코드
포인트를 허용했습니다. 일부 허용된 경로는 이후의 파일 접근 시
`UnicodeEncodeError`를 발생시켰습니다. surrogateescape 값이 UTF-8이 아닌
파일 이름을 생성할 수 있었기 때문입니다.

수정 사항은 기존의 문자열 및 길이 검사 이후에 엄격한 UTF-8 인코딩
가능성을 요구합니다. 유효하지 않은 정책 텍스트는 `invalid_workspace_policy`를
발생시키고, 유효하지 않은 조작 경로에 대한 접근은 `workspace_path_denied`를
발생시킵니다. 유효한 한글, 악센트가 있는 문자, 결합 문자, 상위 평면
(supplementary-plane) 문자는 정확한 값을 그대로 유지합니다. 기존의 NUL
검사, 경로 제한, 문자 수 제한은 그대로 유지됩니다.

추가된 다섯 개의 단위 테스트는 형식이 잘못된 경로, 디렉터리 선택, 조작
접근, 형식이 잘못된 실행 파일/인자 텍스트, 유효한 유니코드 보존을
다룹니다. 독립적인 프로브는 2,048개의 서로게이트 코드 포인트 전체와 유효한
유니코드 파일 입출력(인접한 스칼라 경계 및 JSON으로 디코딩된 이모지 포함)을
검사했습니다. 그 6,177건의 검사가 통과했습니다. 새 테스트를 예전 구현에
적용한 결과 15개의 서브테스트가 실패했으며, 이는 그 테스트들이 원래의
결함을 실제로 탐지함을 확인해 줍니다.

## 다음 구현 게이트

1. **명시적인 effort 및 타임아웃 정책.** 지원되는 CLI 옵션을 검증하고,
   요청된 effort를 불변의 실행 입력과 함께 기록하며, 식별된 연속 실행에
   걸쳐 이를 보존합니다. 호출 지속 시간만으로 느린 호출의 원인을 추론하거나
   조용히 모델을 변경하지 않습니다.
2. **구조화된 출력 호환성.** 네이티브 도구와 MCP가 비활성화된 상태에서
   설치된 CLI의 `--json-schema` 동작을 평가합니다. 런타임 통합을 선택하기
   전에 스트림 파싱, 중복/알 수 없는 필드, 정확한 태스크 아이덴티티, 형식이
   잘못된 결과를 검증합니다. 엄격한 검증을 계속 활성화합니다.
3. **명시적인 복구.** 알려진 최종적(terminal) 형식 오류 응답을 위한
   Codex 승인 경로를 설계하며, 정확한 부모 실행, 보존된 이력, 청구된 예산,
   불확실한 부작용의 재생 없음을 포함합니다. 새로운 시도는 반드시 계속
   보이도록 유지되어야 합니다.
4. **실제 프로젝트 게이트 반복.** 실제 에디터 쓰기, 통과하는 격리된 검사,
   에디터의 정확히 고정된 내보내기에 대한 검토, 명시적인 Codex 승인을
   요구합니다. 오직 그 이후에만 자동 P4/P5 컴포지션을 평가합니다.

0.7.1 입력 검증 수정은 이 네 가지 후속 작업을 구현하지 않습니다. 현재의
실행 및 복구 경계에 대해서는 [워크스페이스](workspaces.ko.md)를
참고하세요.
