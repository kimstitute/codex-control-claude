# 테스트

## 자동화 테스트: 모델 호출 없음

저장소 루트에서:

```bash
python3 -m unittest discover -s tests -v
```

최초 공개 버전의 기준선(baseline)은 47개의 테스트였습니다. 어사인먼트
스위트는 v1 역할/보고서 계약과 v0.3 태스크 생명주기에 대한 커버리지를
추가합니다. `test_tasks.py`는 구조화된 후속 작업, 원자적 동시 제출, 불변
리비전, 정확한 결과 승인, 차단되거나 불일치하는 출력, 보수적인 재시도를
다룹니다. `test_migration.py`는 v1 호환성, WAL 백업, 각 마이그레이션
경계에서의 중단을 검사합니다. 테스트는 임시 디렉터리와 가짜(fake) Claude
프로세스를 사용해 다음을 검증합니다:

- 병렬 용량, 세션별 상호 배제, 요청 중복 제거
- 대상 취소, 타임아웃, 워커 실패, 모호한 실행으로부터의 복구
- 명시적인 재개/재시작 동작과 과거 대화 ID의 보존
- 세션/모델 검증, 형식이 잘못된 출력, 도구 사용 거부, 결과 파일 무결성
- 플러그인을 다른 경로(공백이 포함된 경로 포함)로 재배치하는 경우
- 설치 프로그램의 직렬화, 롤백, 복원 실패 시 백업 보존
- 상태 데이터베이스 실패의 기계 판독 가능한(machine-readable) 처리
- 기존의 도구 비활성화 프로필 하에서 표준입력으로 역할 지시사항이 Claude에
  전달되는지 여부
- 엄격한 어사인먼트 입력, 결정론적 재시도, 변경된 프리셋 충돌
- 이력 보고서 검증, 프롬프트 변조, 형식이 잘못되었거나 잘못된 보고서
  아이덴티티
- 종료, 활성, 실패, 알 수 없음 결과에 대한 다중 실행 관찰

이 테스트들은 Linux 프로세스 기능을 필요로 합니다. 로그인하거나 Claude
계정을 사용하거나 모델 요청을 하지 않습니다.

Ruff가 이미 설치되어 있는 경우 선택적으로 사용할 수 있는 정적 검사:

```bash
ruff check plugins tests install.py
ruff format --check plugins tests install.py
```

## 라이브 통합: 명시적인 계정 사용

라이브 테스트는 실제 Claude 모델을 호출하고, 계정 사용량을 소모하며, 로컬
Claude 세션 이력을 생성합니다. 이들은 unittest 디스커버리에 절대 포함되지
않습니다.

**이 체크아웃 외부의 새 출력 디렉터리**를 사용하세요:

```bash
python3 tests/live_smoke.py \
  --claude-bin /absolute/path/to/claude \
  --output /absolute/path/outside-repository/new-live-check
```

이 스위트는 전용 스토어와 프로젝트를 생성합니다. 중첩되는 Sonnet/Fable
실행, 독립적인 대화 기억(recall), 한 실행 취소 중 다른 실행의 완료, 취소
이후의 재개, 테스트 프로젝트 훅의 미실행 여부를 검사합니다. 계정에서 두
모델 별칭 모두 사용 가능해야 합니다.

출력에는 프롬프트, 응답, 세션 ID, 프로세스 메타데이터, 보고서가 포함됩니다.
이를 비공개 런타임 데이터로 취급하세요. 이 스위트는 또한 테스트 머신에
Claude 자체의 일반적인 영속 대화를 남깁니다. 이 파일들을 커밋하거나 원본
보고서를 공개 이슈에 첨부하지 마세요.

라이브 검사는 개발 중 통과했습니다. 원본 산출물은 이 공개 저장소에서
제외되어 있으며, 여러분의 머신에서 이 스위트를 실행하면 여러분의 CLI
버전과 계정에 대한 증거가 확립됩니다.

더 작은 구조화 위임(delegation) 검사(Sonnet executor 1개와 Fable critic
1개)를 위해서는 체크아웃 외부의 또 다른 새 디렉터리를 사용하세요:

```bash
python3 tests/live_assignments.py \
  --claude-bin /absolute/path/to/claude \
  --output /absolute/path/outside-repository/new-assignment-check
```

이는 중첩 실행, 역할 기본값 기반 모델 라우팅, 독립적인 태스크 아이덴티티,
`observe`, 저장된 프롬프트 검증, 유효한 구조화 보고서,
`acceptance: unreviewed`, 정확한 공급 마커 출력, Claude 도구 호출 0건을 검사합니다. 이
작은 프로브는 연구 품질, 더 큰 병렬성에서의 처리량, 또는 임의의 모델 생성
증거의 정확성을 확립하지 않습니다.

## 라이브 태스크 리비전과 승인

두 번의 실제 모델 호출을 의도적으로 수행하고 구조화된 동일 세션 기억을
검증하려면:

```bash
python3 tests/live_tasks.py \
  --claude-bin /absolute/path/to/claude \
  --output /absolute/path/outside-repository/new-task-check \
  --model sonnet
```

이는 격리된 테스트 스토어를 생성하고, 두 번째 입력에 토큰을 포함하지 않고도
정확한 토큰 기억을 검사하며, 두 리비전 모두에 대해 명시적인 기준 기반 승인을
기록합니다. 이는 동일한 백엔드, v2 보고서, 모델 증거, 변경되지 않은 프로젝트
디렉터리를 검증합니다. `--cli /absolute/path/to/installed/claude_control_cli.py`로
재배치된 설치를 테스트할 수 있습니다. 출력에는 비공개 프롬프트와 ID가
포함되므로 커밋하지 마세요.

성공적인 실행은 이 제한된 텍스트 전용 흐름을 확립할 뿐, 임의의 구현
정확성이나 Claude 셸/편집 도구의 안전한 실행을 확립하지 않습니다.

## 큐와 복구 테스트

`test_scheduler.py`와 `test_scheduler_recovery.py`는 의존성 순환, 승인
게이트, 수동 제출 강제, 대기 용량, FIFO 디스패치, 동시 코디네이터, 정확한
입력 복사, 초과 크기 입력 롤백, 알 수 없는 용량, 명시적 재시도, 워커 실행
전/후 실제 코디네이터 종료를 검사합니다. 이는 결정론적인 20개 작업 승인
검사와 실제 가짜 프로세스의 중첩을 포함합니다. `test_queue_migration.py`는
스키마 4→5 복구를 각 체크포인트마다 검사하고 승인된 v2 이력의 보존을
확인합니다. 더 오래된 마이그레이션 스위트는 별도로 스키마 3→4 커버리지를
유지하며, 새로운 체인 테스트는 3에서 5까지 도달합니다.

Sonnet을 명시적으로 두 번 호출하고 승인 게이트가 있는 부모/자식 워크플로우를
검사하려면:

```bash
python3 tests/live_queue.py \
  --claude-bin /absolute/path/to/claude \
  --output /absolute/path/outside-repository/new-queue-check
```

자식은 정확한 결과 승인 이후에만 시작되며, 별도의 세션에서 부모의 고정된
의존관계 보고서를 통해 그 토큰을 받아 정확히 반환합니다. 검사는 영속화된
이벤트, 중복 디스패치 없음, 변경되지 않은 프로젝트를 검증합니다. 선택적인
`--cli` 인자는 설치된 코드를 검증할 수 있습니다. 이 제한된 검사는 임의의
모델 생성 콘텐츠의 품질에 대해서는 어떤 주장도 하지 않습니다.

## 메시지와 핸드오프

`test_messages.py`, `test_message_recovery.py`, `test_message_migration.py`는
다음 턴 선택, 조작 중복 제거, 암묵적 모델 턴 없음, 순서가 있는 입력, 취소
경쟁, 오래된 대상, 고정된 소스 보고서, 명시적 재전달, 결합된 입력 제한,
크래시 복구, 불변 영수증, 스키마 5→6 마이그레이션을 다룹니다.

의도적인 두 번의 Sonnet 호출 통합 검사를 사용할 수 있습니다:

```bash
python3 tests/live_messages.py \
  --claude-bin /absolute/path/to/claude \
  --output /absolute/path/outside-repository/new-message-check
```

이는 첫 번째 턴 동안 두 개의 지시사항을 큐에 넣고, 그 결과를 고정된
핸드오프로 첨부하고, ID를 역순으로 선택한 뒤, 재개된 두 번째 턴에서 등록
순서대로 전달되는지를 검증합니다. 정확히 반환된 문자열, 메시지당 하나의
영수증, 암묵적/중복 실행 없음, 변경되지 않은 프로젝트가 검사됩니다. 원본
프롬프트와 ID는 비공개 출력 디렉터리에 남습니다. `--cli`로 설치된 코드를
검사할 수 있습니다.

## 제한된 워크플로우

`test_workflows.py`, `test_workflow_recovery.py`, `test_workflow_cli.py`,
`test_workflow_migration.py`는 고정된 정책, 독립적인 세션, 정확한 구조화
검토, 리비전 핸드오프, 예약 예산, 윈도우 지속성, 동시 코디네이터, 중지 경쟁,
잘못된 승인 방지, 제한된 CLI 경계, 스키마 6→7 복구를 다룹니다. 전체 3→7
체인 역시 마이그레이션 이후 워크플로우를 생성, 실행, 중지하는 과정을
검사합니다.

Sonnet 1회와 Fable 1회를 의도적으로 호출하려면:

```bash
python3 tests/live_workflow.py \
  --claude-bin /absolute/path/to/claude \
  --output /absolute/path/outside-repository/new-workflow-check
```

이는 정확한 대상/다이제스트, 기준 판정, 독립적인 세션, 자동 승인의 부재,
명시적인 Codex 승인, 반복 실행 없음을 검사합니다. 이는 자동화된 unittest
디스커버리에 포함되지 않습니다.

## 워크스페이스와 격리된 검사

`test_workspace_policy.py`, `test_workspace_files.py`, `test_workspaces.py`,
`test_workspace_launch.py`, `test_workspace_migration.py`는 경로/명령
권한, Git 스냅샷, 제한된 텍스트 조작, 고정된 무결성, 공유 용량, 취소, 모호한
복구, 실행 아이덴티티 경쟁, 스키마 7→8 마이그레이션을 다룹니다.

`test_workspace_sandbox.py`는 모델 호출 없이 실제 Bubblewrap 격리를
검사합니다: 비공개 호스트 파일과 자격 증명 환경, 네트워크/GPU 접근, 일회용
쓰기, 출력/시간 제한, 취소나 코디네이터 종료 이후의 자식 프로세스 정리.
네임스페이스 격리를 사용할 수 없는 경우 스킵되며, 스킵이 그 호스트에서
워크스페이스를 실행할 수 있다는 증거는 아닙니다. 호스트의 승인된
네임스페이스 지원 환경에서 실행하세요.

Sonnet의 편집/검사에 이어 독립적인 Fable의 고정 파일 검토를 의도적으로
수행하려면:

```bash
python3 tests/live_workspace.py \
  --claude-bin /absolute/path/to/claude \
  --output /absolute/path/outside-repository/new-workspace-check
```

이 합성 Git 픽스처는 4번의 모델 턴, 정확히 편집된 내용, 일회용 네임스페이스
안에서의 명명된 unittest 명령, 변경되지 않은 원본 파일, 독립적인 검토 세션,
명시적인 승인, 중복 호출 없음을 검사합니다. Claude의 네이티브 도구/MCP는
계속 비활성화되며, 파일 조작은 컨트롤러 요청입니다. 비공개 출력에는 프롬프트
및 세션 ID가 포함되므로 공개해서는 안 됩니다.

## 0.7.0 릴리스 검증

최종 릴리스 코드는 완전한 디스커버리 실행에서 Python 3.10과 Python 3.14
모두에서 **258개의 테스트를 모두** 통과했습니다. 두 실행 모두 스킵 없이
실제 Bubblewrap 격리 테스트 6개를 포함했습니다. Ruff, 플러그인/스킬 검증,
저장소 공백(whitespace) 검사도 통과했습니다. 자동화된 실행은 가짜 Claude
프로세스를 사용했으며, 라이브 통합 증거는 위에 별도로 문서화되어 있습니다.

## 0.7.1 실제 프로젝트 검증

최종 런타임 및 테스트 파일은 스킵 없이 실제 Bubblewrap 격리 테스트 6개를
포함해 Python 3.14.6에서 **263개의 테스트**를 통과했습니다. 14개의
워크스페이스 정책 테스트 역시 Python 3.10.18에서 통과했습니다. 소스 파일은
독립적으로 테스트된 사본과 일치하며, 수정된 두 파일은 Fable의 고정 검토
스냅샷과 일치합니다. Ruff, 컴파일, 플러그인/스킬 검증, 공백 검사도
통과했습니다.

실제 에디터 파일럿 자체는 통과하지 **못했습니다**: Sonnet 타임아웃과 별개의
중복 키 보고서가 쓰기나 검사 이전에 중단되었습니다. Codex는 그 코드 제안을
독립적으로 수정하고 테스트했으며, 별도의 읽기 전용 Fable 검토는 APPROVE를
권고했습니다. 출처, 6,177건의 독립적인 경계 검사, 필요한 후속 작업에 대해서는
[파일럿 기록](real-project-pilot.ko.md)을 참고하세요. 에디터 태스크는 여전히
승인되지 않은 상태이며, 검토 산출물의 승인이 이를 바꾸지 않습니다.


## 0.8.0 실행 설정 검증

effort 회귀 그룹은 엄격한 설정 검증, 실행당 명시적 플래그 하나, 원시 및
구조화된 세션 재개, 독립적인 검토자, 워크스페이스 지속성, 이전 보고서/지문
호환성, 다섯 개의 저널 체크포인트 모두에서의 크래시 주입을 포함한 오프라인
8→9 마이그레이션을 다룹니다.

기능 테스트는 예약 없는 미지원 승인, 워커 실행 전의 지원 상실, 슈퍼바이저와
exec 사이의 실행 파일 교체, 래퍼 프로브 없는 1초 실행, 프로브 없는 멱등
재생(replay)을 검사합니다. 큐 테스트는 프리플라이트 도중 도착하는 새 항목,
예약 없는 일시적 프로브 실패, 기록된 디스패치 조작 재생을 검사합니다.

Python 3.10은 새로운 29개 테스트를 모두 통과합니다. Sonnet은 제한된 인자/
검증기 제안을 제공했고, Codex는 지속성과 생명주기 동작을 통합했습니다.
Fable은 보존된 하나의 세션에서 설계와 구현을 검토하고 수정 사항을
승인했으며, 최종 전체 스위트 재실행도 완료되었습니다. 최초의 전체 스위트
실행에서는 원래의 정리(cleanup) 에러 텍스트가 손실된 것이 드러났고, 구현이
수정된 뒤 기존 회귀 테스트가 통과했습니다. 최종 Python 3.14 실행은 스킵
없이 실제 Bubblewrap 격리 테스트 6개를 포함해 292개의 테스트를 모두
통과했습니다. Python 소스와 테스트 해시는 그 최종 실행 내내 고정되어
있었습니다. Ruff, 플러그인/스킬 검증, 로컬 문서 링크도 통과했습니다.

별도의 의도적인 라이브 테스트는 Sonnet `medium` 시작과 정확한 세션 재개
시의 성공적인 nonce 기억, 그리고 Fable `high` 호출을 검증했습니다. 실제 CLI가
보고한 모델은 `claude-sonnet-5`와 `claude-fable-5-1`이었습니다. 세 실행
모두 도구 호출 0건, 모델 대체 없이 완료되었습니다. 기본 스토어는 이 합성
테스트 스토어가 생성되기 전에는 유휴 상태였으며, 점유된 슬롯을 우회하는 데
사용되지 않았습니다. 증거는 요청된 플래그를 기록할 뿐, 독립적으로 측정된
유효 effort를 기록하지는 않습니다.


설치 검증은 32개의 플러그인 파일을 모두 일치시켰고, 검증된 백업을 사용해
유휴 상태의 스키마 8 스토어를 스키마 9로 업그레이드했습니다. 기존 테이블
전반의 모든 이전 열과 rowid는 동일했습니다: 아홉 개의 세션과 열아홉 개의
실행이 보존되었습니다. 모든 이력 보고서는 마이그레이션 전후로 이전 v0.7.1
릴리스와 일치했습니다. 데이터베이스 무결성과 외래 키도 통과했으며, 설치된
코드는 추가 모델 호출 없이 세 개의 라이브 테스트 실행을 모두 읽었습니다.

## 버전 0.9 컴포지션 검증

최종 소스 트리는 302개의 단위 테스트를 통과했습니다. 이 호스트가 필요한
비권한(unprivileged) 네임스페이스를 거부하기 때문에 하나의 Bubblewrap
네임스페이스 테스트 클래스가 스킵되었습니다. 컨트롤러는 격리를 약화시키는
대신 그 환경 제약을 보고합니다. 최종 트리에서 16개의 집중 컴포지션 및
스키마 마이그레이션 테스트가 통과했으며, 여기에는 불변 소스 참조 재생,
크래시 복구, 두 개의 명시적 승인 게이트, 고정된 검토자 생성, 중지 경쟁,
고아(orphan) 정리, 스키마 9→10 이력 보존이 포함됩니다. Ruff, 포맷팅,
Python 컴파일, `git diff --check`도 통과했습니다.

독립적인 Fable 검토는 명시적 high effort와 함께 `claude-fable-5-1`을
사용했으며, 제한된 원샷(one-shot) 컴포지션에 대해 `APPROVE`를
반환했습니다. 그 세 가지 확인 항목은 컴포지션 소유의 승인 쿼리, 파생된
읽기 전용 검토자 정책 테스트, 스냅샷 복사 이전의 P5 내보내기 검증으로
커버됩니다. 이 릴리스에서는 실제 프로젝트 실행이 수행되지 않았는데, 이는
별개의 파일럿 범위이기 때문입니다.
